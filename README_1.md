# Веб-фронт для MCP-моста

Заменяет CLI (`mcp_bridge.py`) на страницу в браузере с полем чата и живой
лентой вызовов MCP-инструментов — то, что раньше печаталось в терминал,
теперь видно прямо в интерфейсе (SSE-стрим).

## Структура

- `bridge_core.py` — логика моста (MCP-клиент + OpenAI-клиент, цикл
  function calling), вынесенная из `mcp_bridge.py` в переиспользуемый
  класс `McpBridge`, без `input()`/`print()`. Та же конфигурация через
  переменные окружения, те же две точки сопряжения с LLM-инфраструктурой
  (LLM-hub и inference model) — см. комментарии в файле.
- `server.py` — FastAPI-приложение: отдаёт статическую страницу,
  `/api/ask?q=...` стримит события по SSE (`config`, `tool_call`,
  `tool_result`, `final`, `limit_reached`, `error`).
- `static/index.html` — сама страница: чат, поле ввода, кнопки с
  готовыми демо-вопросами, живая лента вызовов инструментов под каждым
  ответом бота.
- `requirements.txt` — зависимости (те же три, что у CLI-версии, плюс
  `fastapi`/`uvicorn`).

MCP-соединение и OpenAI-клиент создаются один раз при старте сервера и
живут всё время его работы — вопросы не пересоздают сессию, только
дёргают уже открытое соединение (вопросы сериализуются логом, то есть
обрабатываются по одному — для демо одного оператора этого достаточно).

## Запуск на ВМ

```bash
cd webui
python3 -m venv webui-venv
. webui-venv/bin/activate
pip install -r requirements.txt

# .env — тот же файл, что и для CLI-версии (см. ../.env.example)
export $(grep -v '^#' ../.env | xargs)

uvicorn server:app --host 0.0.0.0 --port 8000
```

Открыть `http://<адрес-ВМ>:8000` в браузере. Если порт 8000 не открыт
наружу — пробросить через SSH: `ssh -L 8000:localhost:8000 user1@<ВМ>` и
открыть `http://localhost:8000` локально.

## Что отличается от CLI-версии

- Один вопрос — один SSE-запрос (`EventSource`), без истории диалога
  между вопросами (как и в CLI-версии — каждый вопрос независим).
- Вызовы инструментов показываются по мере выполнения, а не пачкой в
  конце — для демо это и есть «вау-эффект»: видно, что бот реально
  ходит в каталог, а не выдумывает ответ.
- Точки сопряжения с LLM-hub/inference не изменились — та же логика,
  что в `../mcp_bridge.py` и `../.env.example`.
