# Архитектура: MCP-мост OpenMetadata ↔ LiteLLM

Текущее рабочее состояние (обновлено 04.10.2026): скрипт `mcp_bridge_test.py` на litellm-stack VM связывает function calling LiteLLM с MCP-сервером OpenMetadata. Проверено end-to-end на деле — больше не план.

Оператор задаёт вопрос в терминале litellm-stack VM. `mcp_bridge_test.py` ведёт цикл function calling: отправляет вопрос и список MCP-инструментов в LiteLLM (локально, :4000), LiteLLM делает инференс через Foundation Models API cloud.ru (модель deepseek-v3.2). Когда модель запрашивает инструмент каталога, скрипт как MCP-клиент напрямую вызывает `/mcp`-эндпоинт OpenMetadata на отдельной ВМ (Bearer-токен бота `mcpapplicationbot`), результат возвращается в диалог с моделью — обычно 5–10 таких вызовов до финального ответа. OpenMetadata, отдельно от этого live-пути, ранее подключена коннекторами к сервисам демостенда (нижний блок) — именно оттуда берутся метаданные, которые бот находит.
