# Веб-фронт для MCP-моста

Заменяет CLI (`mcp_bridge.py`) на страницу в браузере с полем чата и живой
лентой вызовов MCP-инструментов — то, что раньше печаталось в терминал,
теперь видно прямо в интерфейсе (SSE-стрим).

## Структура

- `bridge_core.py` — логика моста (MCP-клиент + OpenAI-клиент, цикл
  function calling), вынесенная из `mcp_bridge.py` в переиспользуемый
  класс `McpBridge`, без `input()`/`print()`. Та же конфигурация через
  переменные окружения, те же две точки сопряжения с LLM-инфраструктурой
  (LLM-hub и inference model) — см. комментарии в файле.
- `server.py` — FastAPI-приложение: отдаёт статическую страницу,
  `/api/ask?q=...` стримит события по SSE (`config`, `tool_call`,
  `tool_result`, `final`, `limit_reached`, `error`).
- `static/index.html` — сама страница: чат, поле ввода, кнопки с
  готовыми демо-вопросами, живая лента вызовов инструментов под каждым
  ответом бота.
- `requirements.txt` — зависимости (те же три, что у CLI-версии, плюс
  `fastapi`/`uvicorn`).

MCP-соединение и OpenAI-клиент создаются один раз при старте сервера и
живут всё время его работы — вопросы не пересоздают сессию, только
дёргают уже открытое соединение (вопросы сериализуются логом, то есть
обрабатываются по одному — для демо одного оператора этого достаточно).

## Запуск на ВМ

```bash
cd webui
python3 -m venv webui-venv
. webui-venv/bin/activate
pip install -r requirements.txt

# .env — тот же файл, что и для CLI-версии (см. ../.env.example)
export $(grep -v '^#' ../.env | xargs)

uvicorn server:app --host 0.0.0.0 --port 8000
```

Открыть `http://<адрес-ВМ>:8000` в браузере. Если порт 8000 не открыт
наружу — пробросить через SSH: `ssh -L 8000:localhost:8000 user1@<ВМ>` и
открыть `http://localhost:8000` локально.

## Что отличается от CLI-версии

- Один вопрос — один SSE-запрос (`EventSource`), без истории диалога
  между вопросами (как и в CLI-версии — каждый вопрос независим).
- Вызовы инструментов показываются по мере выполнения, а не пачкой в
  конце — для демо это и есть «вау-эффект»: видно, что бот реально
  ходит в каталог, а не выдумывает ответ.
- Точки сопряжения с LLM-hub/inference не изменились — та же логика,
  что в `../mcp_bridge.py` и `../.env.example`.

## Токены, защита от «вызова текстом»

- Под каждым ответом выводится расход токенов за вопрос (вход / выход / число
  вызовов модели), в ленте — токены по шагам, в шапке — счётчик за сессию
  страницы (хранится в `sessionStorage` вкладки, кнопка «сбросить»). Если шлюз не
  вернул `usage`, цифра оценивается по длине текста и помечается «~».
- Если модель написала вызов инструмента текстом, мост просит повторить через
  function calling (`MCP_BRIDGE_PSEUDO_RETRIES`, по умолчанию 2). Температура —
  `MCP_BRIDGE_TEMPERATURE` (по умолчанию 0.2, пусто = не передавать).

## Набор инструментов, таймаут, очередь

- `MCP_BRIDGE_TOOLS_ALLOW` — какие MCP-инструменты видит модель. По умолчанию только чтение:
  `search_metadata, semantic_search, get_entity_details, get_entity_lineage, describe_entity_type`.
  Инструменты записи (`create_entity`, `patch_entity`, `create_lineage`, `create_test_case`)
  модели недоступны, а попытка вызвать инструмент вне списка отклоняется. `*` — отдать все.
  Меньше инструментов — меньше токенов входа на каждом шаге и быстрее ответ.
- `MCP_BRIDGE_LLM_TIMEOUT` — таймаут одного вызова модели, секунд (по умолчанию 120). Вместо
  бесконечного «думает…» страница покажет ошибку.
- Вопросы обрабатываются по одному; если сервер занят, страница пишет «в очереди».
- Ответ бота отображается как Markdown (таблицы, заголовки, списки) через `marked` + `DOMPurify`;
  оба файла лежат в `static/vendor/`, внешние CDN не нужны.

## Граф lineage (Mermaid)

Если модель вызывала `get_entity_lineage`, сервер разбирает ответ инструмента, собирает узлы и связи
(до 60 узлов) и присылает событие `graph`; страница рисует схему `flowchart LR` под ответом
(цвета по типам: хранилище, пайплайн, таблица, дашборд). Библиотека mermaid лежит локально в
`static/vendor/` (без CDN), `securityLevel: strict`, SVG дополнительно проходит DOMPurify.
Если граф не появился, а связи должны быть, смотрите `journalctl -u mcp-webui | grep lineage`:
туда пишется ответ инструмента, который не удалось разобрать. Если lineage в каталоге пуст, графа не будет.

Проверка каталога ограничена четырьмя типами сервисов: databaseService, dashboardService,
pipelineService, storageService (остальные, только если спросить явно) — это закреплено в системном промпте.

## Запуск локально

```bash
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # заполнить значения
set -a; source .env; set +a
uvicorn server:app --host 127.0.0.1 --port 8000
```

Нужен доступ до MCP OpenMetadata и до LiteLLM (из внутренней сети).

## Развёртывание на ВМ

Код в `/opt/mcp-webui`, секреты в `/opt/mcp-webui/.env` (chmod 600), юнит — `deploy/mcp-webui.service`
(`sudo cp deploy/mcp-webui.service /etc/systemd/system/ && sudo systemctl daemon-reload && sudo systemctl enable --now mcp-webui`).
Обновление: скопировать файлы поверх и `sudo systemctl restart mcp-webui`.
Порт 8000 в группе безопасности открывать только для нужных адресов.
