# Демо-сценарий: MCP-бот для OpenMetadata

Oct 4, 2026 · @Dimi

## Цель демо

Показать, что AI-ассистент (deepseek-v3.2 через LiteLLM) может отвечать на вопросы о каталоге данных OpenMetadata, используя MCP-инструменты каталога напрямую — без ручного похода в UI. Аудитория видит: обзор подключённых источников, проверку тенантной изоляции и PII-тегирования, и ответ на конкретный бизнес-вопрos по данным компаний A и B.

## Подготовка (за 15–30 минудо демо)

- [ ] Проверить, что сетевой доступ к VM есть (VPN/публичный IP cloud.ru доступен)
- [ ] Ссылки доступа под рукой: `id_rsa` для demo stand и openmetadata-vm, пароль/ключ для litellm-stack VM
- [ ] `OPENMETADATA_TOKEN` в `.env` на litellm-stack VM действителен (токен бота `mcpapplicationbot` не истёк)
- [ ] Манифест `s3://datasets/openmetadata.json` на месте (содержит reports, company\_a/raw, company\_b/raw) — иначе датасеты компаний пропадут из каталога

**Известные ограничения, которые не стоит пытаться исправить в процессе демо:**

- Sample Data в UI пуст для всех таблиц/контейнеров (регрессия после миграции, не исправлена)
- `semantic_search` на MCP-сервере не включён — бот использует только ключевой `search_metadata`
- Ответ бота занимает 10–30 секунд (до 10 вызовов инструментов) — это норма, не зависание

## Шаг 1. Включение стенда

1. В консоли cloud.ru включите все нужные VM: demo stand (`10.0.0.5`, AD/LDAP, Keycloak, OPA, Postgres, ClickHouse, Airflow, MinIO, Superset), openmetadata-vm (внешний `176.123.165.177`, внутренний `10.0.0.7`), litellm-stack VM.
2. Дайте 2–3 минуты на поднятие сервисов в контейнерах (docker compose стартует автоматически при включении VM, если раньше не делали `docker compose down`).
3. Проверить готовность OpenMetadata: открыть `http://176.123.165.177:8585` в браузере, дождаться экрана входа — это знак, что бэкенд и база данных поднялись.
4. (Опционально, для вводной части демо) зайти в UI и показать аудитории каталог визуально: 4 подключённых сервиса (MinIO, Airflow, Postgres, ClickHouse) — чтобы затем было наглядно сравнить с тем, что найдёт бот.

**Ожидаемый результат:** все VM работают, OpenMetadata UI открывается, сервисы в разделе Services на месте.

## Шаг 2. Запуск MCP-бота

Зайти по SSH на litellm-stack VM и выполнить:

```bash
cd /opt/litellm-stack
export $(grep -v '^#' .env | xargs)
. mcp-bridge-venv/bin/activate
python mcp_bridge_test.py
```

**Что должно появиться сразу:**

```
[MCP] Доступно инструментов: 13
  - search_metadata: ...
  - get_entity_details: ...
  - get_entity_lineage: ...
  ...
Вопрос:
```

Если скрипт вывел список инструментов и ждёт строку ввода «Вопрос:» — мост работает, можно начинать демо. Для каждого вопроса из шага 3 просто вводите текст и Enter; скрипт завершается после одного ответа — для следующего вопроса запускайте `python mcp_bridge_test.py` снова (venv уже активирован, повторять только эту команду).
